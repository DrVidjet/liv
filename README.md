# Маленький космос

Небольшое личное веб-приложение: **меню на день из того, что есть дома** (рецепты подбираются в реальном времени с [food.ru](https://food.ru)), дела, календарь тренировок, созвездия и коллекция сохранённых рецептов. Внутри есть руководство пользователя (раздел «📜 Как пользоваться»).

- Бэкенд — один файл на Python, **только стандартная библиотека**, без зависимостей.
- Фронтенд — один `index.html` (стили, скрипт и фоновые картинки внутри).
- Личные данные (продукты, дела, календарь, дневник питания, сохранённые рецепты) хранятся в `localStorage` браузера. На сервере только общие исключения, «Не предлагать» и кеш ответов food.ru (SQLite).

## Структура

```
serve.py               HTTP-сервер: статика + API подбора меню
ingredients.py         сопоставление продуктов: синонимы, «кухонная база», роли «к подаче», КБЖУ перекусов
public/index.html      всё приложение
public/guide.html      руководство пользователя (подгружается в раздел «Как пользоваться»)
public/guide/*.webp    скриншоты для руководства
deploy.sh              деплой на сервер одной командой
nginx/liv.conf         nginx: наружу на :80, лимит запросов к API
systemd/liv-web.service  сервис
tools/guide-shots.mjs  пересъёмка скриншотов для руководства
```

## Локальный запуск

Нужен Python 3.12+ (зависимостей нет) и доступ в интернет до food.ru.

```bash
mkdir -p state
STATE_DIRECTORY=./state PORT=8080 python3 serve.py
```

Открыть http://localhost:8080/. Сервер слушает только `127.0.0.1`.

| Переменная        | По умолчанию      | Что это                                   |
|-------------------|-------------------|-------------------------------------------|
| `STATE_DIRECTORY` | `/var/lib/liv-web`| где лежит `recipes.sqlite3` (кеш и списки)|
| `PORT`            | `8080`            | порт                                      |

База создаётся и мигрирует сама при старте.

## Как подбирается меню

1. По продуктам из «Что есть дома» (кроме приправ, соусов и того, что едят «как есть») сервер ищет на food.ru: сам продукт, пары продуктов, а для мяса/птицы/рыбы — шире («суп курица», «курица в духовке», «курица рис», 3 страницы выдачи). Страница поиска food.ru отдаёт у каждого рецепта полный список ингредиентов — по нему считается, чего не хватает.
2. Соль, сахар, перец, мука, масло, специи, вода и т. п. считаются всегда имеющимися; сушёные специи и травы не считаются недостающими.
3. Рецепты с исключёнными продуктами и скрытые («Не предлагать») отбрасываются. Исключение бывает «совсем» или «только блюда из него» (например, яйца: омлет нельзя, тесто с яйцом можно).
4. Раскладка по приёмам пищи: обед — сначала супы; обед/ужин — блюдо с мясом/птицей/рыбой + отдельный гарнир, если в блюде нет крупы или картошки; полдник — сладкое, закуски и перекусы без готовки из продуктов «к подаче» (хлебцы + паста + варенье, мороженое + ягоды…), с чередованием основ.
5. Если включено «Можно докупить лук, чеснок или морковь» — примешиваются блюда, которым не хватает ровно одного такого продукта (примерно 1 из 3), с пометкой «докупить».
6. Для выбранных блюд читается страница рецепта (schema.org/Recipe): граммовки, шаги, КБЖУ на порцию.

Ответы food.ru кешируются: поиск — 12 часов, страницы рецептов — 14 дней. Первый подбор на новом наборе продуктов — 5–10 секунд, дальше быстро.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/menu?have=…&have=…&buy=…&mode=home\|shop&turn=N&shift=a,b,c,d&side_shift=a,b,c,d&almost=1\|0` | меню на день. `turn` — номер «Подобрать другое меню», `shift`/`side_shift` — перелистывания блюда/гарнира по приёмам пищи |
| GET | `/api/recipe-state` | исключения (`{name, mode}`) и скрытые рецепты |
| POST | `/api/excluded` | `{"name": "Яйца", "block": true, "mode": "all"\|"dish"}` |
| POST | `/api/blocked` | `{"name": "…", "block": true, "url": "https://food.ru/recipes/…"}` |

POST принимает только `application/json` и отклоняет чужой `Origin`.

## Деплой

Настройки сервера — в `.env.deploy` (он в `.gitignore`):

```bash
cp .env.deploy.example .env.deploy   # и заполни
./deploy.sh
```

| Переменная | По умолчанию | |
|---|---|---|
| `LIV_HOST` | — | адрес сервера (обязательно) |
| `LIV_USER` | — | пользователь с sudo; от него же работает сервис (обязательно) |
| `LIV_PORT` | `22` | порт ssh |
| `LIV_PASS` | — | пароль для ssh и sudo (нужен `sshpass`). Без него ssh и sudo спросят сами; лучше ssh-ключ |
| `LIV_KEEP` | `5` | сколько релизов хранить |

Переменные можно задать и в окружении: `LIV_HOST=… LIV_USER=… ./deploy.sh`.

Что делает скрипт:

1. Проверяет синтаксис Python и заливает файлы в `~/liv-upload` на сервере.
2. Под sudo создаёт `/srv/liv-web/releases/release.<дата>` и атомарно переключает симлинк `/srv/liv-web/current`.
3. Ставит/обновляет systemd-юнит (`User=` подставляется из `LIV_USER`), если он изменился, и перезапускает `liv-web`.
4. Ждёт ответа `/api/recipe-state`; если сервис не поднялся — **откатывается на прошлый релиз** и показывает журнал.
5. Ставит nginx при первом запуске, обновляет `liv.conf`, если он изменился, проверяет ответ через nginx.
6. Удаляет старые релизы, оставляя `LIV_KEEP` последних.

### Новый сервер

Достаточно Ubuntu/Debian с `python3`, `rsync`, пользователем из `LIV_USER` с правами sudo и открытым 80-м портом — дальше `./deploy.sh` всё поставит сам (сервис, nginx, папки).

Сервер отдаёт приложение по http без авторизации. Если он смотрит в интернет, подумай о домене с HTTPS (например, certbot для nginx) и базовой авторизации: серверные списки «Что исключить» и «Не предлагать» общие для всех, кто открыл страницу.

### Откат вручную

```bash
ls -1dt /srv/liv-web/releases/release.*            # список релизов, свежие сверху
sudo ln -sfn /srv/liv-web/releases/release.<…> /srv/liv-web/current.tmp
sudo mv -T /srv/liv-web/current.tmp /srv/liv-web/current
sudo systemctl restart liv-web
```

### Логи

```bash
journalctl -u liv-web -f
sudo tail -f /var/log/nginx/access.log
```

## Руководство и скриншоты

Текст — `public/guide.html` (открывается и отдельно, и внутри приложения: ссылки `#…` и `id` получают префикс `g-`, чтобы не совпасть с разделами приложения).

Переснять скриншоты после изменений интерфейса (нужны Node 22+ и Chromium, ImageMagick для конвертации):

```bash
STATE_DIRECTORY=./state PORT=8080 python3 serve.py &
node tools/guide-shots.mjs http://localhost:8080/ /tmp/liv-shots /tmp/liv-chrome-profile
for f in /tmp/liv-shots/*.png; do magick "$f" -quality 82 "public/guide/$(basename "${f%.png}").webp"; done
```

Скрипт кладёт демо-продукты и дела только во временный профиль браузера и не нажимает кнопки, меняющие серверные списки. Если имена снимков поменялись, обнови `width`/`height` у `<img>` в `guide.html`.
